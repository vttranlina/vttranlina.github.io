Highlights

Team Calendar scheduling

  • The initial fallback for moved Team Calendar invitations could misclassify events created directly in a team calendar. The team selected database metadata rather than user-editable ICS metadata to retain the original invitation owner; implementation is now in pull/480.
  • Routing replies without Team Calendar ICS metadata is covered across Sabre pull/481, side-service pull/1057, and integration tests pull/335.
  • pull/480 remains open with a CodeScene quality gate failing on string-heavy arguments. Related regression test pull/329 is waiting for the upstream Sabre change.

Meet integration

  • Shared Meet configuration, API client, token exchange, and token-provider abstraction were extracted from host delegation into pull/1051. This isolates the architectural identity choice from delegation and room creation.
  • Deployment prerequisites and risks are now documented: an empty ApplicationDomain allow-list fails open, and provisional-user reconciliation requires global OIDC settings that permit sub replacement. The current decision accepts this because SSO emails are unique, but it differs semantically from ADR 056.
  • Room lookup now follows pagination as a stopgap; the intended upstream solution is a Meet room-listing slug filter rather than scanning all pages (pull/1051 review comment).
  • Frontend room creation still has unresolved product behavior in pull/1247: server enablement should be explicit, Meet failures should be surfaced rather than silently falling back, and rooms created before event save may be orphaned.

ICS video-link compatibility

  • Google Calendar removed Twake video links because the existing separator matched Google’s own footer boundary. Merged pull/1054 introduces a distinct separator for booking-generated ICS descriptions.
  • Frontend pull/1356 supports legacy and new separators, but review requested release sequencing to avoid requiring exact simultaneous deployment. The proposed order is frontend compatibility first, then backend activation of the new separator.

Scheduling and recurring events

  • Merged pull/476 preserves attendee-specific recurring overrides when the master participation changes; regression coverage was added in pull/331.
  • Merged pull/478 restores detached occurrences when attendees are invited only to selected instances, with coverage in pull/333.
  • Organizer validation is now enforced at scheduling time, including Team Calendar behavior, through merged pull/479. The old CALDAV_ORGANIZER_VALIDATION test setup was removed in merged pull/334.

Operations and frontend

  • issues/1055 exposed that Calendar creates SaaS domains only after mail DNS validation. Manual creation remains the migration workaround; the longer-term direction is to create domains after ownership verification and enforce sending restrictions separately.
  • Open pull/1056 adds POST /contacts?action=republish; it has human approval but a test-duplication quality gate and requires a corresponding Calendar Admin task.
  • Merged pull/1059 fixes booking proposal replies so they target the booker instead of the no-reply address.
  • Open pull/1361 addresses the month-view day offset reported in issues/1360.

Review & Discussion Signals

  • The Meet authentication model remains an explicit architectural question: application credentials let side-service assert user identity, whereas ADR 056 would carry the user’s authentication to Meet. The provider abstraction avoids blocking delivery, but the final model is not yet settled (pull/1001 comment).
  • Meet sub rewrites during provisional-user reconciliation are reportedly not logged. This needs upstream consideration because the enabled identity transition otherwise leaves no audit trace (pull/1051 comment).
  • For SaaS domains, adding an activated field was explicitly rejected as the direct fix. The preferred direction separates domain ownership from permission to send, but there is not yet enough signal on implementation ownership or timing (issues/1055 comment).
